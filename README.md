# MedAgent · 医疗分诊 Agent 小平台

> 一个**不做诊断**的医疗 Agent：根据症状给出首诊科室、识别危险信号、提示就诊准备。
> 重点不在「能聊」，而在**边界**——什么能说、什么必须拒绝、什么时候必须让人去看医生。

参考 [Datawhale《Hello-Agents》](https://github.com/datawhalechina/hello-agents) 的架构思路实现：
ReAct 式工具编排 + 记忆/检索 + 护栏 + 离线评测，纯标准库，零依赖，可离线演示。

---

## 一、为什么做这个

医疗是「Agent 出错代价最高」的场景之一：普通助手答错一句没人受伤，医疗助手答错一句可能延误就诊。
所以这个项目不追求「像医生」，而是把三件事做扎实：

1. **先救命**：命中红旗症状（胸痛伴冷汗、意识改变、卒中征象等）→ 直接给急救指令，不再输出其他内容
2. **不越界**：不诊断、不开方、不给剂量；求诊断/求处方的请求一律拒答，并说明「我能做什么」
3. **可追溯**：每一步「想了什么 → 调了什么工具 → 看到什么」都记录，并落审计日志（只存哈希，不存原文）

## 二、架构

```
浏览器（单页）
   │  POST /api/chat
   ▼
FastAPI 风格的标准库 HTTP 服务（app.py）
   │
   ├─ Agent 主循环（agent/core.py）
   │    1. check_red_flag  ──► 命中则直接返回急救应答（1 步结束）
   │    2. triage          ──► 首诊科室（规则 + 同义词扩展）
   │    3. search_kb       ──► 本地知识库检索（就诊前能做什么）
   │    4. drug_lookup     ──► 药品通用注意事项（不给剂量）
   │    5. 护栏复核 → 组装回答 →（可选）LLM 润色 → 再过一次护栏
   │
   ├─ 工具层（agent/tools.py）     4 个纯数据工具，可单测
   ├─ 护栏层（agent/guard.py）     拒答 / 软化表述 / 强制免责
   └─ 审计层（app.py）             JSONL：会话、哈希、红旗、耗时
```

### 三层护栏

| 层 | 位置 | 做的事 |
|---|---|---|
| 输入侧 | `guard.detect_diagnosis / detect_prescription` | 识别「我是不是得了X」「该吃什么药」并拒答 |
| 决策侧 | `tools.check_red_flag` | 红旗优先，命中即短路，不做其他推理 |
| 输出侧 | `guard.soften / with_disclaimer` | 把「你得了」改成「可能与…相关」；每条回答强制附免责声明 |

## 三、评测（这是本项目最重要的部分）

三套用例，对应三种不同的「相信程度」：

| 数据集 | 条数 | 用途 | 通过率 |
|---|---|---|---|
| `eval/cases.json` | 20 | 边写规则边改，相当于**训练集** | 20/20 = 100% |
| `eval/holdout.json` | 10 | 一开始没调过参，用来验证泛化 | 1/10 = **10%** |
| `eval/holdout.json`（加同义词层后） | 10 | 看错误后加了通用同义词表 | 10/10 = 100% |
| `eval/blind.json` | 8 | **写完即测、不回头改**，估计真实水平 | 2/8 = **25%** |

**结论（也是这个项目最值钱的一句话）：**

> 规则法在「见过的说法」上几乎满分，在「没见过的说法」上只有 25%。
> 因为它匹配的是**字面**（“腹痛”），而用户说的是**说法**（“肚子痛”“肚子疼得直不起腰”）。
> 同义词表能救一部分，但它本质上是在为测试集打补丁——一旦你看着测试集改，测试集就变成了训练集。

**这正是需要 LLM 的地方**：把「说法 → 结构化症状」这一步交给模型，规则只负责兜底和终裁。
项目已经预留了接口（`agent/llm.py`），设置 `OPENAI_API_KEY` 后会对答案做润色，但**不改变护栏判断**——
换句话说，模型可以决定「怎么说」，不能决定「能不能说」。

复现：

```bash
python eval/run_eval.py                              # 训练集
CASES_FILE=eval/holdout.json python eval/run_eval.py  # 留出集（Linux/macOS）
$env:CASES_FILE="eval/holdout.json"; python eval/run_eval.py   # Windows PowerShell
CASES_FILE=eval/blind.json python eval/run_eval.py    # 盲测集
```

## 四、怎么跑

```bash
cd medagent
python app.py
# 打开 http://127.0.0.1:8000
```

零依赖（只用 Python 标准库）。可选：设置 `OPENAI_API_KEY` 开启答案润色。

页面功能：

- 输入症状 → 看到**回答 + 执行轨迹 + 红旗/拒答标记 + 耗时**
- 「跑评测」按钮 → 直接看 20 条用例的通过率
- 「审计日志」→ 看最近请求的会话、红旗命中、耗时（不含原始文本）

```
│   ├── blind.json         盲测集 8 条
│   └── run_eval.py        评测脚本
└── static/index.html      单页前端
```

## 六、已知局限（面试时主动说，比被问出来好）

1. **规则法的天花板就是 25%**（盲测集），换说法就崩；真正的解法是 LLM 做意图抽取 + 规则做终裁。
2. **知识库只有 10 条**，覆盖不了真实场景；生产环境要接权威指南并做版本管理与更新。
3. **药品数据是示例**，仅含通用名与注意事项，不含剂量、相互作用库、禁忌证表。
4. **没有做多轮追问**：真实分诊需要追问（持续多久、有无发热、既往史），当前是单轮。
5. **审计只存哈希**，便于演示隐私设计，但不便于回溯具体对话；生产中应配合脱敏留存。

## 七、下一步（按优先级）

1. 接 LLM 做**结构化抽取**（症状/时长/伴随症状/红旗线索）→ 规则只做终裁，盲测集目标 ≥80%
2. 加**多轮追问**：缺字段时主动问，而不是一次猜完
3. 加**向量检索**替换关键词检索（embedding + rerank）
4. 加**红队用例**：诱导诊断、诱导用药、伪装成医生的越权请求
